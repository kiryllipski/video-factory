## Что это и как устроено

Конвейер повторяет проверенную архитектуру облачной фабрики, но каждый узел заменён на
локальный open-source аналог. Стадии:

```
тема → 1.сценарий(LLM) → 2.комплаенс(LLM) → 3.план кадров(LLM) → 4.генерация кадров(диффузия)
     → 5.озвучка(TTS) → 6.субтитры(STT) → 7.сборка(HTML/CSS+ffmpeg) → 8.QA
```

Целевой стек машины (Mac M4 Pro, 48 GB): Ollama (LLM) · ComfyUI (изображения) · Chatterbox
(TTS) · whisper.cpp (субтитры) · ffmpeg (+ опц. hyperframes для HTML-анимации). Детали —
`docs/DEPLOY_M4PRO.md`, `docs/ARCHITECTURE_LOCAL.md`.

Карта документов:
- `docs/ARCHITECTURE_LOCAL.md` — стадии, контракты данных, структура `runs/`.
- `docs/DEPLOY_M4PRO.md` — что и в каком порядке ставить, какие модели качать.
- `docs/IMAGE_PROMPTING.md` — как строить промпты под выбранную image-модель (ключевой док стадии 3/4).
- `docs/STRATEGY.md` — универсальные бенчмарки и правила (retention, длины, метрики).
- `roles/*.md` — системный промпт под каждую стадию (это промпты для локальной LLM/оператора).
- `contracts/schemas_local.py` — Pydantic-контракты между стадиями (интерфейс, не менять без нужды).
- `config/pipeline.config.example.json` — конфиг стека (пути, модели; ключей нет).
- `config/channel.template/` — ниша-агностичный шаблон канала (заполняется под нишу позже).
- `scaffold/engine_local.py` — СКЕЛЕТ оркестратора (функции-заглушки с TODO — тебе их реализовать).
- `reference/` — справочные наработки фабрики (ресёрч + плейбук). Это **контекст для решений**, не
  инструкции. Индекс с пояснениями «что/кому» — `reference/INDEX.md`. Сверяйся с ними по стадиям:
  сценарий → `01_short_form_retention`; комплаенс → `02_wellness_safe_claims_pl_eu`; промпты картинок
  → `41_local_image_prompting`; TTS → `26_tts_pacing`; сборка → `23`/`27`/`28`; QA → `24`; стратегия
  канала → `38`; **выбор ниши в Задаче 0 → `34_niches_sergey_health`**.

### 0.1 Аудит окружения (выполни сам, командами; ничего не устанавливай)
Собери и покажи Сергею короткий отчёт (таблица «есть/нет/версия»):
- OS/чип/архитектура: `uname -m` (ждём arm64), `sw_vers`; свободное место на диске (нужно ~60-70 GB): `df -h /`.
- Базовое: `brew --version`, `git --version`, `python3 --version` (ждём 3.10+), `node --version` (ждём 22+, если будем собирать через hyperframes), `xcode-select -p`.
- Медиа: `ffmpeg -version | head -1`.
- LLM: `ollama --version` и `ollama list` (какие модели уже скачаны).
- Изображения: установлен ли **ComfyUI** (поищи каталог: `ls ~/ComfyUI ~/comfyui 2>/dev/null`, процессы, порт 8188), **Draw Things** (`ls /Applications | grep -i draw`), любые diffusion-модели/веса на диске (`find ~ -iname "*.safetensors" -o -iname "*.gguf" 2>/dev/null | head`).
- TTS/STT: установлен ли whisper.cpp, chatterbox, kokoro, любые torch-окружения (`pip list 2>/dev/null | grep -iE "torch|chatterbox|kokoro|whisper"`).
- Python-окружение: есть ли активное venv/conda, менеджер пакетов (`pip`, `uv`, `poetry`).

Не делай выводов «наугад» — если команда не нашлась, так и пиши «не установлено».
Особое внимание: у Сергея **может уже стоять ComfyUI** и часть моделей — переиспользуй их, не ставь заново.

### 0.2 Уточняющие вопросы Сергею (задай, дождись ответов)
1. **Ниша канала**: longevity/биохакинг или фитнес-наука (или другое)? — чтобы заполнить `config/channel.template/`.
2. **Языки**: только EN (Tier-1, рекомендовано) или ещё RU/PL? — влияет на выбор TTS-голоса и модели whisper.
3. **Image-модель для старта тестов**: FLUX.1-schnell (Apache, коммерч.-чистая) / FLUX.1-dev / Qwen-Image / Z-Image / SDXL. Если не знает — предложи начать со schnell (см. `docs/IMAGE_PROMPTING.md`, матрица выбора).
4. **Голос**: есть ли у него 10-сек референс-сэмпл для клонирования в Chatterbox, или брать встроенный голос?
5. **Платформы и длина**: YT Shorts (30-40с) / TikTok (>61с) / Reels — что первично? (см. `docs/STRATEGY.md`).
6. **Сборка**: ставим Node+hyperframes ради HTML/CSS-анимации кадров, или пока обойтись голым ffmpeg (Ken Burns через `zoompan`)? — влияет на объём установки.
7. **Сколько роликов в день** он планирует — калибровка под «асинхронную фабрику».

## Задачи после Задачи 0 (порядок ориентировочный, уточни планом из 0.3)

1. **Установка стека** по `docs/DEPLOY_M4PRO.md` — только то, чего нет по аудиту; переиспользуй существующее.
2. **Скачать модели** под выбор из 0.2 (LLM, image-модель, TTS, whisper).
3. **Реализовать `scaffold/engine_local.py`** по контрактам `contracts/schemas_local.py` и ролям `roles/*.md`:
   каждую стадию — как функцию, артефакты на диск в `runs/<дата>_<slug>/`, атомарная запись,
   пропуск готовых стадий при перезапуске (16GB-паттерн неактуален — 48GB тянет параллель, но
   контракты те же). Строго локально, без сетевых вызовов к платным API.
4. **Заполнить `config/channel.template/`** под выбранную нишу (studio_context + media_plan).
5. **Smoke-тест** по чек-листу из `docs/DEPLOY_M4PRO.md` → один тестовый ролик end-to-end.
6. Показать ролик Сергею, собрать правки, зафиксировать конфиг.

## Правила
- **Никаких облачных ключей и платных API.** Если чего-то не хватает локально — предложи локальную замену, не подключай облако молча.
- Лицензии TTS: Kokoro (Apache 2.0) и Chatterbox (MIT) — коммерчески чисты. **XTTS-v2, F5-TTS, Fish Speech — НЕ использовать** для монетизируемых видео (non-commercial). Image-модель: FLUX.1-dev — non-commercial; для монетизации предпочтительны schnell/Qwen/Z-Image (см. IMAGE_PROMPTING).
- Каждый ролик воспроизводим: фиксируй seed/версии, всё пишем в `runs/<...>`.
- Музыку локально не генерируем — используем папку готовых лицензированных треков.
- Перед необратимым (удаление, перезапись, большие скачивания) — спрашивай Сергея.
