## Сценарий → `script.json` (схема `Script`)

Формат файла (валидные значения обязательны):
```json
{
  "lang": "en",
  "hook": "строка ≤200 симв — суть в первые 1–3 сек, без приветствий",
  "beats": [
    {
      "voiceover": "текст озвучки бита, короткие разговорные фразы",
      "on_screen_text": "2–4 слова (караоке-субтитр, safe-зона)",
      "visual_cue": "что показать в кадре — вход для visual_director",
      "dur_s": 2.0
    }
  ],
  "cta": "строка ≤160 симв — save/share/follow",
  "total_dur_s": 28.0,
  "poster_text": "≤4 слов (v3): постер первого кадра, *акцент* жёлтым",
  "cta_plate": "≤5 слов (v3): финальная плашка — бинарный вопрос"
}
```

Жёсткие лимиты схемы (нарушишь — `validate_run.py` не пропустит):
- `beats`: от 3 до 20 штук. Каждый `dur_s` в диапазоне **0.8–4.0** сек.
- `total_dur_s`: **15–90**; **v4-таргет 20–45с** (владелец 2026-08-04, было жёстко 22–32с) —
  тема определяет длину, свит-спот completion ~25-35с остаётся ориентиром, не потолком/полом.
  Сумма `dur_s` битов ≈ `total_dur_s`.
- `hook` ≤200, `cta` ≤160, `poster_text` ≤48, `cta_plate` ≤48 символов.

Правила ретеншена (research/01 + аналитика VitalLogic, growth_plan_2026-07-13):
- **Хук = первая секунда.** Никаких «Hi / Today I'll tell you». Сразу суть по формуле хука из
  studio_context канала (противоречие фактов, унижение авторитета, curiosity gap, цифра/конкретика,
  pain point). Мёртвая тишина/вдох в начале = гарантированный свайп.
- **v2: симптом/боль — голосом за ≤1.5 сек.** Первый бит открывается СИМПТОМОМ/болью зрителя
  («Skurcze nóg w nocy?»), а не веществом/термином («Magnez: tlenek czy…»). Вещество живёт в
  заголовке (поиск), симптом — в звуке и постере (свайп-тест). Первый бит ≤2.5с, симптом —
  в первых 3 словах. Жаргона в хуке нет вообще (провалы недели 1–4: fotouczulenie, kurkumina).
- **v2: `poster_text` обязателен** — самая острая формулировка симптома/ставки на языке канала.
  Рендерится КРУПНО в верхней трети с t=0 (кадр-0 = «обложка» в ленте Shorts, свайп решается
  по нему). Не дублируй дословно заголовок — сожми до удара.
- **v3: постер ≤4 слов + акцент-слово.** Чем короче, тем крупнее шрифт (авторазмер сборки:
  ≤16 симв → 132px). Самое цепляющее слово выдели звёздочками — «Włosy *na szczotce*?» —
  сборка подсветит фирменным жёлтым. Сборка сама кладёт скрим-градиент — текст читается на
  любом кадре, но верхнюю треть кадра-0 всё равно держи спокойной.
- **v3: хук-лаборатория (обязательный мини-шаг).** Прежде чем зафиксировать script.json,
  напиши **3 варианта пары «хук (голос) + poster_text»** и выбери лучший по чек-листу:
  (a) симптом — в первых 2 словах; (b) постер ≤4 слов и читается за 0.3с; (c) конкретика
  (сцена/число/объект), не абстракция; (d) без жаргона; (e) зритель узнаёт СЕБЯ («это про
  меня»). Отвергнутые варианты сохрани комментарием в qa.json → notes (дёшево, полезно для
  аналитики хуков).
- **v3: `cta_plate` обязателен** — короткий бинарный вопрос (≤5 слов), напр.
  «Tlenek czy *glicynian*?». Рендерится плашкой в верхней трети на последнем бите тем же
  стилем, что постер → визуальная петля «конец = начало» + толчок написать коммент.
  Обычно = сжатый вариант `cta`/`pinned_comment`.
- **Хук ↔ тело (анти-clickbait).** То, что обещал хук, раскрой в первые ~5 сек тела. Не откладывай payoff.
- **v2: бит 2 НЕ пересказывает хук.** Провал по текстам v1 (пример — kolagen-timing: 5.2с из 27.8
  ушло на повтор заголовка). Бит 2 = сразу механизм/конфликт/цифра. Если хук — вопрос, бит 2 —
  первая часть ответа, не перефраз вопроса.
- **v4: закрытая петля (`loop_closure`) — решение под тему, не default** (владелец 2026-08-04).
  Витамин-D-ролик (177% avg viewed) — один прецедент, не правило на каждый выпуск. Реши,
  просится ли ИМЕННО эта тема на визуальную петлю; если нет — не форсируй её, финальный кадр
  всё равно должен разрешать конфликт бита (см. §«визуальный ДОВОД бита» ниже), не быть
  дефолтной заготовкой из ролика в ролик. Вопрос-CTA остаётся всегда, петля/не петля его не отменяет.
- **Хронометраж как структура:** ~0–3с хук → ~3–10с углубление/боль → ~10–25с раскрытие (reward) →
  финал CTA. Для 30–50-сек ролика держи 12–20 битов по 1.5–2.5с.
- **Open loop на 10–12с:** бит-мостик, обещающий ещё более важное дальше («But that's not the worst part…»).
- **Биты короткие и разговорные.** `voiceover` — живая речь ~150 wpm, без канцелярита и длинных периодов.
  Помни: длину ролика ведёт озвучка (per-beat TTS), поэтому короткий бит = быстрый монтаж.
- **`on_screen_text` — 2–4 ключевых слова** бита (это фолбэк-субтитр, если whisper не распознает; основные
  субтитры — караоке по словам из транскрипта). Пиши самое «цепляющее» слово бита.
- **CTA** из studio_context (save/share). По возможности — seamless loop: последнее слово → первое слово хука.
- **Тон** строго из studio_context. Для YMYL-каналов (wealth_viz и т.п.) — см. `qa_and_compliance.md`
  (запрет обещаний, дисклеймеры) ещё на этапе письма, чтобы комплаенс не переписывал заново.

## План кадров → `frame_plan.json` (схема `FramePlan`)

Формат:
```json
{
  "grade": "единый грейд/палитра ролика (из studio_context §Визуальный код)",
  "light": "единая схема света",
  "lens": "оптический язык, напр. '35mm documentary' / '85mm macro'",
  "frames": [
    {
      "prompt": "промпт Nano Banana 2 (EN) по формуле ниже",
      "aspect": "9:16",
      "ref_ids": [],
      "motion": "ken_burns_in",
      "start_s": 0.0,
      "dur_s": 2.0
    }
  ]
}
```

Лимиты/значения:
- `frames`: минимум 3. **РОВНО один кадр на каждый бит, в том же порядке** (`frames[i]` ↔ `beats[i]`).
  Число кадров = числу битов. `start_s`/`dur_s` копируй из тайминга бита (движок пересчитает под озвучку).
- `motion` — одно из: `ken_burns_in`, `ken_burns_out`, `pan_left`, `pan_right`, `parallax`, `static_hold`.
  По умолчанию `ken_burns_in`; **чередуй** для динамики; статики >3с быть не должно.
- **`ref_ids` — референс-картинка ОПЦИОНАЛЬНА (2026-07-17, factory_audit).** По умолчанию `[]` —
  консистентность держит только текстовый `GRADE/LIGHT/LENS` (см. ниже), никакая референс-картинка
  не передаётся. Заполняй `ref_ids` (напр. `["frame_00"]`) **только когда кадр обязан буквально
  повторить того же персонажа/сцену** — типичный случай: кадр-петля в конце ссылается на кадр-0
  (тот же человек, разрешённое состояние симптома). Не используй референс «для консистентности
  стиля вообще» — раньше так делали всегда (hybrid anchor: кадр-0 + предыдущий на КАЖДЫЙ кадр), и
  это утекало не только грейд, но и композицию кадра-0 (у него нарочно пустая верхняя треть под
  заголовок) в кадры, которым эта пустота не нужна — визуально давало поля/леттербокс в готовом
  кадре. Плюс: без лишних референсов кадры естественнее выходят разными — это то, что и так
  требует ротация крупности/сюжета (см. ниже).
- `grade`/`light`/`lens` — **одинаковые на весь ролик** (консистентность). Бери из studio_context §5.

### Формула промпта кадра (Nano Banana 2, research/29 + /03)
Порядок важен — GRADE/LIGHT/LENS идут первыми (модель приоритезирует ранние блоки):

```
[Action] + [Subject] + [State] + [Setting] + [Style] + [Technical]
```
- **Композиция 9:16:** ключевой субъект в верхних двух третях, по центру/левее; **нижняя треть чистая**
  (туда лягут субтитры); ничего важного на правом крае и верхних ~15% (там UI платформ).
- **Текст и предметы:** описывай чистую сцену позитивно, но не обнуляй смысловые надписи. Если
  бит про этикетку/состав, разрешены крупный предмет и короткая печатная этикетка с нужной
  строкой; если бит про телефон/монитор — разрешён простой экранный UI, пиктограммы,
  таймер или график. Не используй «no text» для таких кадров. Длинные таблицы, абзацы,
  случайная AI-типографика и водяные знаки остаются запрещены. Реальные бренды, названия и
  логотипы разрешены, если они нужны сцене; запланированный текст не искажать.
- **Юр-чистота:** реальные живые лица — только public-domain или явная стилизация; не воспроизводить
  реальных живых людей узнаваемо. Исторические компании/люди — ок.
- build_media САМ добавит в каждый промпт префикс `GRADE/LIGHT/LENS` и негатив-блок
  (`over-saturated, 3d render, plastic, cartoon, mutated geometry, random text, white border,
  photo/polaroid frame`) — тебе дублировать не нужно, пиши в `prompt` только содержание кадра.
  Но держи описание в едином стилевом ключе грейда.
- ⚠️ **Осторожно со словом «vignette» в `grade`/`light`** (найдено 2026-07-04 на реальном рендере
  `fedex-saved-by-5000-in-vegas`): Nano Banana 2 иногда трактует «vignette»/«archival»/«sepia print»
  вместе как инструкцию нарисовать **физическую винтажную фотографию с белой бумажной рамкой**,
  а не мягкое затемнение углов светом. Негатив-блок в build_media теперь блокирует рамку, но лучше
  избегать самого слова — пиши «soft corner darkening from lighting» вместо «vignette».

### Пейсинг (research/01 §3, /04)
- План кадра ≤2.5с; смена крупности/перебивка каждые ~2с; нет статики >3с (иначе QA пометит).
- **v2: кадры синхронны битам.** Сборка держит `frames[i]` ровно на длительности бита i
  (по реальному TTS), а не равномерно — кадр обязан соответствовать смыслу СВОЕГО бита.

### v2: первый кадр = постер (growth_plan этап 1)
Кадр-0 — «обложка» ролика в ленте Shorts, поверх него сборка кладёт `poster_text` крупным
текстом в верхней трети. Требования к промпту кадра 1:
- **Человеческий контекст, не предмет:** рука/силуэт/бытовая сцена, связанная с симптомом
  (человек, схватившийся за икру; рука на будильнике; усталое утро у окна). ЗАПРЕТ на
  «банка/капсула на столе» в кадре 1 — это главный визуальный штамп провалов v1.
- **Высокий контраст + спокойная верхняя треть** под текст постера — но формулируй это
  ФОТОГРАФИЧЕСКОЙ причиной, не языком вёрстки (2026-07-17, factory_audit: фразы вида «upper
  third clean for headline» / «fills the canvas edge to edge» модель иногда понимает буквально
  как «нарисуй отдельную пустую плашку сверху», а не единую фотографию — получается кадр,
  склеенный из фото + полосы, вместо full-bleed снимка). Пиши так, будто ставишь камеру:
  «low-angle shot looking slightly up, so a plain wall/ceiling rises naturally behind the subject
  and fills the upper frame, softly out of focus» — пустота обоснована ракурсом/боке/архитектурой
  кадра, а не «зарезервирована под текст». Результат для сборки тот же (верх спокойный → туда
  ляжет заголовок), но модель рендерит один целостный снимок. Нижняя треть по-прежнему чистая
  под субтитры — этой формулировкой (уже проверена, работает) можно и дальше пользоваться как есть.
- Эмоция кадра = эмоция симптома (дискомфорт/усталость/вопрос), не «рекламная красота».
- **v3: проблема ВИДИМА и КРУПНА.** Аудит ремейка wlosy-zelazo: «щётка с несколькими
  волосками» → волосы не читаются, эмоция не срабатывает. Пиши промпт так, чтобы сама
  проблема была преувеличенно заметна с миниатюры за 0.3с: «brush FULL of tangled hair»,
  «alarm clock showing 3:47 AM», «visible dark under-eye circles». Стесняться драматизации
  сцены не нужно (в рамках вкуса канала) — это единственный кадр, который решает свайп.
- **v3: движение кадра-0 сборка ставит сама** (`hook_punch` — быстрый зум-удар первых 0.5с);
  в плане motion первого кадра можно оставить любой — он будет переопределён.

### v3: кадр = визуальный ДОВОД бита (запрет «обоев»)
Каждый кадр обязан ПОКАЗЫВАТЬ утверждение своего бита, а не «сопровождать» его. Аудит: на
бите «Zanim wydasz pieniądze…» стоял кадр «блокнот и стакан воды» — обои, связь нулевая.
Тест при написании промпта: закрой voiceover и спроси «что утверждает этот кадр?» — если
ответ «ничего/уют», перепиши. Приёмы: конфликт объектов (кофе РЯДОМ с капсулой железа),
преувеличенная деталь (ладонь с горкой из 6 капсул), процесс (кипяток заливает зелёный
порошок), а не натюрморт.

### Разнообразие/сцепка кадров (монтаж по Соколову — `research/56`)
Против визуального однообразия (болезнь VitalLogic: 8/10 кадров = одинаковая макро-капсула). Соседние
кадры должны **сцепляться замыслом и при этом различаться** — не «ещё один тот же предмет». Правила при
написании `prompt`-ов кадров:
- **Ротация крупности (№1, главное):** чередуй ступени {extreme_macro · macro · medium · wide/environment
  · abstract}. **Не 2 кадра подряд одной крупности**; на ~10 кадров — ≥3–4 разные ступени.
- **Разнообразие сюжета, не только предмета:** product-macro / texture-ingredient / lifestyle-context
  (быт, окружение) / human-moment (рука/жест) / symbolic-pairing / abstract. **Не >2 «предмет-на-фоне» подряд.**
- **Ротация ракурса** (top_down / eye_level / low_hero / 45°) и **смещение субъекта по третям** между кадрами.
- **Ken Burns как эстафета:** push_in на деталь, pull_out на wide; горизонт. паны не разворачивай на 180° встык.
- **Свет/цвет:** варьируй направление света; акцентный цвет готовь заранее (он ~на ⅓ уже в предыдущем кадре).
- НЕ применимо к статичным кадрам: фаза/скорость движущихся объектов, строгое правило оси 180° (`research/56` §«не тянуть»).
