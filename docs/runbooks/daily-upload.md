Канал: **@VitalLogic-nutriFlow** (YouTube Shorts, польский, БАД/wellness).
Репозиторий (cwd для всех команд): `/Users/kirillipski/Desktop/mytools/0-video production`.

**Полномочия.** Этот runbook описывает отдельный операционный контур публикации. Производство
можно выполнять по активному v8-контракту, но загрузка, публикация, расписание и любое изменение

локальные производственные вызовы не расширяет это разрешение.

**⚠️ Каденс с 2026-08-13 — 1 ролик в день (решение владельца).** Было 2/день; второй ролик дня

`CADENCE_SLOTS_UTC` в `youtube.py`. Цель, к которой идём: побить рекорд канала 4865 просмотров
за 48 часов (30–31 июля).
Возврат к 2/день — только по решению владельца.

## Часть A — загрузка 1 ролика

1. Сначала дозалить зависшие:
   ```bash
   python3 autopilot_factory/publishers/youtube.py retry-pending --channel vitallogic_bad_pl
   ```
   Сообщение про лимит — не страшно, продолжай.

2. Найти готовые к загрузке прогоны: перебрать `autopilot_factory/runs/vitallogic_bad_pl/*/`.
   Готов, если внутри есть `out.mp4` и `publish_package.json`, и НЕТ `post_result.json`,
   и НЕТ `upload_pending.json`, и **НЕТ `hold.json`**.

   `hold.json` — ручная задержка: ролик собран, но владелец ещё не посмотрел (или мы не
   хотим публиковать эксперимент). Заведено 2026-08-15, когда первые ролики расширенного
   набора рубрик и экспериментальный стеклянный прогон оказались в очереди раньше, чем
   владелец успел их оценить. Снять задержку = удалить файл.

   **Порядок при каденсе 1/день — сначала текущая версия пайплайна** (`pipeline_version` в
   `publish_package.json`; сейчас 8.0), внутри версии — по имени папки по возрастанию. Прогоны
   старых версий идут заполнителями, когда роликов текущей версии нет. Правило поменялось
   2026-08-13 вместе с каденсом: одного слота в день хватает на ~20 дней очереди, и если грузить
   «старые вперёд», когорта v7 выйдет в эфир только через три недели — учиться будет не на чем.

3. **Слот публикации не вычислять самостоятельно** — ни по `publish_log.jsonl`, ни по «сегодня +
   каденс». Источник истины только один — живой запрос к YouTube через `--publish-at auto`.

4. Взять **первый** (по порядку из шага 2) готовый ролик и загрузить его:
   ```bash
   python3 autopilot_factory/publishers/youtube.py upload-batch --channel vitallogic_bad_pl \
     --run autopilot_factory/runs/vitallogic_bad_pl/<run1> \
     --privacy private
   ```
   Слот подбирается по каденсу **1/день, 06:00 Europe/Warsaw** (= 04:00 UTC) и печатается
   (`[schedule] --publish-at auto → выбран слот ...`) — включить строку в сводку. Слот всегда
   ближайший свободный, поэтому очередь просто растягивается вперёд по одному ролику в день.
   Бронирование атомарно (живой запрос к YouTube + файловый лок между процессами,
   `_reserve_slot_lock` в `youtube.py`) — наложение слотов исключено структурно, не только
   соглашением звать `upload-batch` вместо цикла `upload`. `upload-batch` оставлен и на один
   ролик: если каденс вернут к 2/день, менять придётся только `CADENCE_SLOTS_UTC`, не рунбук.

   Без `--no-archive` и без `--no-synthetic` — дефолты (архивация в iCloud + пометка AI-контента)
   обязательны, не переопределять.

   Если на каком-то ролике вернулся `uploadLimitExceeded` — `upload-batch` сам останавливает
   батч на этом ролике (остальные всё равно упадут по тому же лимиту); зафиксировать это в сводке
   и перейти к части B, не пытаться догружать вручную в этом прогоне.

## Часть B — пополнение запаса

5. Посчитать **запас в днях эфира** = готовые к загрузке прогоны (как в шаге 2; часть загруженных
   уже архивировалась и пропала из `runs/`) + уже запланированные на канале ролики (их печатает
   `upload-batch`, либо `_scheduled_occupied_utc` в `youtube.py`). При каденсе 1/день один ролик =
   один день эфира.

6. Запас **5 дней или больше** → пополнение не нужно, перейти к сводке. Порог снижен с 6 роликов
   2026-08-13: при 1/день прежняя цель разгоняла очередь быстрее, чем эфир её съедает, и правки
   пайплайна доходили до зрителя с задержкой в недели.

7. Запас **меньше 5** → произвести `N = 5 - <запас>` новых роликов, но **не больше 2 за прогон**,
   **строго последовательно**, один за другим. Это жёсткое ограничение `CLAUDE.md`:
   `engine_v8.py --build` / `hyperframes render` никогда не запускать параллельно — раньше вешало машину.

   **Производить текущей версией пайплайна — v8 Codex.** Сначала Codex создаёт полный пакет
   по [Codex Shorts skill](../../skills/codex-viral-shorts/SKILL.md), затем после принятия
   кадров ImageGen сборка выполняется явно:
   ```bash
   cd autopilot_factory && VITALLOGIC_TTS_VOICE=Charon \
     python3 engine_v8.py --build runs/vitallogic_bad_pl/<run> \
     --asset-channel vitallogic_bad_pl
   ```
   `engine_v8.py --go` для Codex-пакетов не используется: он может делегировать редакционные
   решения Gemini. Дубли проверять по `runs/` И по iCloud.

   Для каждой новой темы:

   a. Прочитать целиком `autopilot_factory/channels/vitallogic_bad_pl/editorial_policy.md`
      и `autopilot_factory/channels/vitallogic_bad_pl/studio_context_v8_pl.md`
      (рубрики, хук-формулы, визуальный код, комплаенс, CTA) и `media_plan_v8.md` (опубликованные
      темы + несобранные пункты очереди — собирать их в первую очередь).

   b. Тему брать из медиаплана `channels/vitallogic_bad_pl/media_plan_v8.md` (там уже
      проставлены рубрика, формат и угол). Если план исчерпан — сначала собрать широкий
      кандидатный пул по `autopilot_factory/channels/vitallogic_bad_pl/editorial_policy.md`
      и внешним сигналам спроса (`orchestration/research/67_external_demand_sources.md`),
      затем присвоить теме рубрику и формат. Рубрика — производственный контракт, не фильтр
      допустимых областей.
      **Проверить дубли не только по `media_plan_v8.md`, но и по факту** — перечислить папки в
      `autopilot_factory/runs/vitallogic_bad_pl/` И в iCloud
      `~/Library/Mobile Documents/com~apple~CloudDocs/external storage/video/0.5/vitallogic_bad_pl/`
      (обе — источник истории тем, `runs/` неполна после архивации).
      ⚠️ Дубли уже случались: `kurkumina-bez-pieprzu` произведён дважды (2026-07-05 и 2026-07-17) —
      двойная трата плюс каннибализация собственного охвата.

      ⚠️ Микс рубрик v1–v6 («50% Objaw→Błąd / 30% Zła Para / 20% Mit») отменён 2026-08-14.
      `schemas_v8.ACTIVE_RUBRICS` задаёт мягкий fallback и анти-монокультурный контроль;
      не превращай его веса в жёсткий медиаплан и не сужай поиск до добавок.

   c. Прочитать [Codex Shorts skill](../../skills/codex-viral-shorts/SKILL.md) и
      [artifact contract](../../skills/codex-viral-shorts/references/artifact-contract.md).
      Написать в `autopilot_factory/runs/vitallogic_bad_pl/<дата>_<slug>/`:

      `frame_plan.json`, `qa.json`, `publish_package.json`, `codex_strategy.json` и после

      **Комплаенс обязателен:** режим зависит от предмета темы и `rubric`. Для добавок и


      Починить ошибки (не предупреждения) перед следующим шагом.

   e. Собрать и **дождаться завершения** прежде чем начинать следующий ролик:

      Это тратит ~$0.5–0.7 и несколько минут — нормально, уже авторизовано.
      Потолок стоимости ролика — $3 (поднят владельцем 2026-08-13).

   f. Если frame-QA после лимита попыток принял кадр с непройденным чеком — зафиксировать в сводке,
      не блокировать прогон.

8. Новые ролики из этого шага **не грузить в этом же прогоне** — они пойдут завтра (часть A
   следующего дня). Это специально: не публиковать в день производства, держать производство и
   публикацию разнесёнными по времени.

9. Если производство одного из N упало (Gemini API / диск / т.п.) — зафиксировать в сводке и
   не пытаться производить оставшиеся в этом прогоне. Лучше меньше, но без сбоя на всю задачу;
   запас останется чуть ниже 6 до завтра.

## Известные грабли

- **Диск.** `hyperframes render` падает с `ENOSPC` (rc=228) при заполненном диске. Чистить
  `npm cache` и `~/.cache/hyperframes/whisper` (whisper не нужен — ASR в пайплайне не используется).
- **Суточный лимит загрузок** неверифицированного канала — отсюда `retry-pending` в шаге 1.
- **Задвоение слотов публикации — устранено на уровне кода (2026-08-03).** Живой запрос к
  YouTube закрыл вычисление слота по локальным файлам (2026-07-27); атомарный файловый лок
  между процессами (`_reserve_slot_lock`, `youtube.py`) закрыл гонку из-за задержки индексации
  uploads-плейлиста (2026-08-02). Наложение слотов исключено структурно независимо от того,
  вызван `upload-batch` или отдельные `upload` — подробности в `_upload_one`/`_reserve_slot_lock`.
