# Pipeline v8 alpha3 — Gemini-first evidence workflow

Статус: рабочая русскоязычная оценочная версия рядом с v7. Production v7 не заменён.
Публикация отключена (`publication_authorized=false`).

## Что изменено относительно v7

1. До сценария Gemini Pro с Google Search создаёт grounded research memo.
2. Отдельный Gemini-проход нормализует его в `ResearchPack`: источники, `claim_id`,
   разрешённые формулировки, ограничения и rejected-claims.
3. Сценарий обязан привязать факты и числа к `claim_id`. Rejected-claim блокирует run.
4. Compliance, fact-check и смысловой QA выполняются отдельными Gemini-вызовами.
5. После каждой content revision все зависимые проверки выполняются заново.
6. Publish package создаётся только для окончательно принятой версии и содержит URL из
   ResearchPack.
7. Медиа запускается только после pre-media release gate. Стабильный слой v7 сохранён:
   Nano Banana 2, Gemini TTS (`gemini-3.1-flash-tts-preview` через локальный `audio_agent`),
   HyperFrames, субтитры, safe zones, BGM и loudness. Другой TTS-движок не подменяет Gemini
   без прямого указания владельца.
8. Кадровый контракт v8: один смысловой бит → один исходный кадр. Post-TTS дробления по
   трём секундам нет.
9. Poster живёт только до первой фактической смены изображения. Кириллический safe-fit
   учитывает самое длинное слово, а HyperFrames layout-inspect блокирует обрезанный или
   вышедший за canvas зрительский текст.
10. Overlay-gates удаляют информационный шум: одинаковые стороны `versus`, длинные фразы в
    двух колонках, общие подписи «энергия/значение», подпись, совпадающую с субтитром, и
    второй пересказ рядом с числовым callout.
11. Финал использует последний уже принятый кадр. Отдельная image-генерация payoff больше не
    просит «место под карточку», поэтому модель не рисует в фотографии пустую плашку.
12. Перед последней фразой стоит 0.48 с тишины; финальный TTS-бит медленнее и получает
    отдельную нисходящую каденцию. TTS-кэш теперь привязан к text/voice/style/model/speed.
13. Source-overlay использует выбранный владельцем вариант A: крупный тезис, тип источника,
    title, publisher, year и домен. Библиография подставляется детерминированно только из
    ResearchPack, а карточка входит через seek-safe `power3.out` и короткий stagger.
14. Для будущих сценариев Gemini может один раз сказать «Согласно исследованию…» или
    «По данным исследования…», если ссылка естественно поддерживает body/turn. Это не
    обязательная церемониальная вставка; названный источник обязан существовать в ResearchPack.
15. Для польского VitalLogic голос по умолчанию — мужской Gemini `Charon`
    (`VITALLOGIC_TTS_VOICE=Charon`). Подача: яркая, экспрессивная, эмоциональная,
    разговорная и с лёгкой иронией; смена голоса возможна только по прямому указанию владельца.
16. Зрительская речь не использует нерасшифрованные медицинские аббревиатуры (`LDL`, `ApoB`,
    `HbA1c` и подобные). Сначала выбирается подтверждённая простая формулировка; если
    техническое различие необходимо, оно объясняется в том же бите. Число, объект и единица
    произносятся одной законченной фразой, а его overlay появляется в этом же бите не позднее
    0.5 с после произнесения числа. TTS-бит не обрывает незаконченную грамматическую мысль.

## Блокирующие gates

- high-risk claim требует минимум два источника;
- числа без `claim_id`, неизвестные и rejected claims запрещены;
- абсолютные доказательные формулировки и ложная эквивалентность запрещены;
- проверяются акты, payload/payoff, формат, русский язык и соответствие кадра claim;
- JSON Gemini проходит JSON parse и полный Pydantic-контракт, до трёх retry;
- синхронный model call ограничен 180 секундами;
- сохранённые ResearchPack и прошедшая revision возобновляются после сетевого сбоя;
- финальный MP4: 1080×1920, H.264/AAC, три vision-QA стоп-кадра, единый revision/hash manifest.
- planned/actual duration фиксируется как диагностический сигнал темпа, но сама по себе не
  блокирует релиз: приоритет — цельный качественный сторителлинг и читаемость.
- перед render запускается text-layout gate: `canvas_overflow` и `clipped_text` для poster,
  stats, versus, callout, bar, source-card и payoff останавливают сборку;
- source-overlay без зрительского `source_finding` на 3–10 слов блокируется до медиа.

## Запуск

Текстовый прогон без дорогих медиа:

```bash
cd autopilot_factory
python3 engine_v8.py \
  --topic 'Тема ролика' \
  --rubric really_true \
  --format myth_autopsy \
  --angle 'один точный угол' \
  --slug short-slug
```

Сборка уже принятого content package:

```bash
VITALLOGIC_TTS_VOICE=Charon \\
python3 engine_v8.py --build runs/vitallogic_v8_ru/<run-dir>
```

Полный прогон одним вызовом возможен через `--go`, но для оценочных партий рекомендуется
сначала просмотреть `research_pack.json`, `script.json`, `fact_review.json`, `qa.json` и
`release_gate.json`.

Тесты:

```bash
PYTHONPATH=autopilot_factory:orchestration \
  python3 -m unittest -v autopilot_factory/test_engine_v8.py
```

## Что сознательно не включено

- post-TTS нарезка кадров при превышении трёх секунд;
- OCR каждого исходного и финального кадра;
- обязательный `not_a_clone` gate и генерация 3–5 hook-вариантов;
- новое позиционирование канала, актовая озвучка/ASR и живой польский голос;
- фирменный стеклянный «рентген»-гибрид.

Эти пункты остаются отдельными экспериментами, а не частью обязательного v8-контракта.

## Известные ограничения alpha3

- Pixel QA v7 не понимает намеренное загрязнение/увядание и может зря перегенерировать
  доказательный кадр. Нужен claim-aware контекст исключений.
- Layout-inspect надёжно ловит выход текста за canvas, но смысловую перегруженность по-прежнему
  должен остановить upstream gate; технически помещающийся длинный `versus` всё равно плох.
- Image API сохраняет JPEG-байты с расширением `.png`; браузер их читает, но некоторые
  внешние утилиты ориентируются на расширение и требуют предварительной конвертации.
- `gemini-3.1-pro-preview` отклоняет часть вложенных Pydantic response schemas, поэтому v8
  использует Gemini JSON mode + локальную строгую Pydantic-валидацию.
