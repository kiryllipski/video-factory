# План разворачивания локального пайплайна — MacBook Air M3, 16 GB (Надя)

> Хендофф-документ: передай этот файл Codex-агенту на целевой машине и попроси развернуть
> по шагам. Основа — ресёрч `orchestration/research/37_local_opensource_stack.md` (2026-07-02).
> ⚠️ Названия моделей и размеры файлов проверяй на момент установки — экосистема быстро меняется.

## Что строим

Локальная фабрика faceless-видео 9:16 (Shorts/Reels/TikTok) без затрат на API.
Конвейер повторяет стадии основного проекта (`autopilot_factory/engine.py`):

```
тема → сценарий (LLM, JSON) → кадры 9:16 (диффузия) → озвучка (TTS)
     → word-level субтитры (STT) → сборка (HTML/CSS + ffmpeg)
```

## Ключевое ограничение устройства

16 GB unified memory: ОС забирает ~4-5 GB, рабочий лимит **~11 GB**. Держать LLM и
диффузию в памяти одновременно НЕЛЬЗЯ — начнётся swap и пайплайн замедлится в десятки раз.
**Паттерн «строгой последовательности»**: оркестратор загружает → использует → принудительно
выгружает каждую модель. Air без вентилятора — при батчах >30 мин возможен троттлинг,
длинные прогоны дели на паузы.

## Целевой стек

| Узел | Инструмент | Модель | RAM | Скорость (M3) |
|---|---|---|---|---|
| Сценарии/JSON | Ollama (HTTP API) | `qwen2.5:7b` (Q4_K_M) | ~4.5 GB | ~30-35 ток/с |
| Изображения 9:16 | Draw Things (+ ComfyUI-DrawThingsWrapper для скриптов) | Z-Image Turbo 6B (запасной: SDXL) | ~8-10 GB | 20-60 с/кадр |
| Озвучка | Python `kokoro` | Kokoro-82M (Apache 2.0 — коммерчески чистая) | <1 GB | мгновенно |
| Субтитры | whisper.cpp (Metal) | `medium` (ggml, квант.) | ~2 GB | 2-4 с на ролик |
| Сборка | ffmpeg (+ hyperframes, если делаем HTML-анимацию как в основном проекте) | — | <1 GB | — |
| Музыка/SFX | ⛔ НЕ генерировать локально | локальная папка готовых треков | — | — |

Чем жертвуем vs облако: длинная креативная логика сценариев (уровень Gemini Pro) и
микро-детализация кадров (уровень FLUX/Nano Banana). Для массового продакшена достаточно.

## Шаги разворачивания (для Codex)

Диск: суммарно **~20-25 GB**. Предустановлено: Homebrew, Git, Python 3.10+.

1. **База**: `brew install ffmpeg` (+ `node@22`, если собираем через hyperframes: `npm i -g hyperframes` или `npx hyperframes`).
2. **LLM**: установить Ollama (ollama.com) → `ollama pull qwen2.5:7b`.
   В оркестраторе все вызовы `http://localhost:11434/api/generate` обязаны содержать
   `"keep_alive": 0` (немедленная выгрузка весов) и `"format": "json"` для структурного вывода.
3. **STT**: `git clone https://github.com/ggerganov/whisper.cpp && cd whisper.cpp && make metal`
   → `bash ./models/download-ggml-model.sh medium`.
   Word-level таймкоды: `./main -m models/ggml-medium.bin --max-len 1 --output-json voice.wav`.
4. **TTS**: `pip install kokoro soundfile misaki` — веса (~200 MB) подтянутся при первом запуске.
   Проверить доступные голоса под EN (и RU/PL, если нужно — поддержка заявлена с v1.0, проверить качество ушами).
5. **Изображения**: установить Draw Things из Mac App Store → внутри скачать Z-Image Turbo
   (или SDXL как fallback). Для скриптовой автоматизации: `git clone https://github.com/comfyanonymous/ComfyUI`
   + `pip install -r requirements.txt` + кастом-нода `ComfyUI-DrawThingsWrapper`
   (ComfyUI как API-оркестратор, рендер — быстрым бэкендом Draw Things).
   Формат кадров: 896×1152 или 1080×1920 через апскейл (генерация 512×896 → Real-ESRGAN/Upscayl ×2).
6. **Оркестратор**: python-скрипт со стадиями как в основном проекте; артефакты каждой
   стадии — на диск (`runs/<дата>_<тема>/`), атомарная запись, пропуск готовых стадий при
   перезапуске. Строго: одна тяжёлая модель в памяти за раз (LLM → выгрузка → диффузия → выгрузка → TTS).

## Приёмочный smoke-тест
1. `ollama run qwen2.5:7b` — сценарий из 5 реплик в JSON.
2. Один кадр 9:16 через Draw Things ≤90 с.
3. Kokoro: WAV одной реплики; whisper.cpp по нему — JSON с пословными таймкодами.
4. ffmpeg: кадр + WAV → mp4 1080×1920 (h264, yuv420p, 30fps).
5. Полный прогон одной темы end-to-end, пиковая память ≤12 GB (смотреть Activity Monitor).
